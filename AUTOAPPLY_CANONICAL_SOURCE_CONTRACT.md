# Canonical AutoApply source contract

Status: ACTIVE. This file applies to the current source lineage and release gates.

## Purpose

Real-employer acceptance runs are discovery harnesses. Findings are generalized into provider-neutral browser mechanics. Employer/job-specific hotfixes and production overlays are not canonical implementation.

## Apply invariant

Apply is the unattended execution plane after Hunter's single customer Approve & Submit mandate. Apply may create internal browser/form integrity snapshots, but it must never create a second customer-facing approval boundary.

## Canonical browser rules

- Generic DOM/ARIA execution is always available; provider recipes only optimize.
- Application-entry transitions use bounded semantic mechanics, never employer-specific selectors.
- File roles are inferred from semantics/labels and exact plan context; file bytes are SHA-256 verified in the browser.
- Verified upload evidence may survive SPA element replacement only inside the same current plan/session.
- Teach MUNSHI is attempted before bounded Sonnet reversible mechanics.
- Sonnet may return reversible mechanics; it cannot decide final submit, passwords, OTP/MFA, CAPTCHA, identity, or protected values.
- Account creation and normal email verification use the hosted account/mail plane.
- Final submit is bound to the exact approved destination/action/method and current form digest.
- Submission is VERIFIED only from exact action evidence plus independent employer-facing completion evidence. Generic IDs, created/accepted status, unrelated requests, or DOM mutation alone are insufficient.
- Ambiguous employer outcome becomes SUBMISSION_UNVERIFIED and is never automatically resubmitted.

## Retired / forbidden source patterns

Active runtime must not contain employer/job-specific names, IDs, URLs, or selectors; production-only patch directories as source authority; customer-facing second approval flows; or optimistic upload/submission success shortcuts.

Historical code may remain in Git history for archaeology, but it must not be reachable from the active product path.
