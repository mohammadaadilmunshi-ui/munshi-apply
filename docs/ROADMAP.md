# Delivery roadmap

The architecture baseline defines Phases 0 through 17. Delivery uses smaller mergeable milestones with measurable gates.

| Milestone                      | Scope                                                                                     | Exit gate                                             |
| ------------------------------ | ----------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| M0 Foundation                  | Monorepo, contracts, MV3 panel, scanner, IndexedDB, SQLite, CI                            | All local and CI checks pass                          |
| M0.5 Cross-device feasibility  | Responsive private workspace, iPhone tests, secure sync design, desktop handoff           | Physical-iPhone workflow gates and threat review pass |
| M1 Profile and résumé vault    | Complete protected profile, résumé hashes, imports, immutable per-application selection   | Round-trip, integrity, and migration tests pass       |
| M2 Universal understanding     | Frame aggregation, Shadow DOM discovery, sections, navigation, validation, dynamic fields | Synthetic lab coverage meets target                   |
| M3 Pre-flight                  | Job context, answer resolver, confidence policy, sensitive answers, preview               | No unresolved/high-risk item can pass silently        |
| M4 Verified autofill           | Native controls, uploads, state waits, post-action verification                           | Every supported interaction has success evidence      |
| M5 Multi-step AutoPilot        | Workflow state machine, checkpoints, recovery, final review                               | Crash and interruption recovery pass                  |
| M6 Intelligence                | Evidence graph, retrieval, provider router, budget engine, generated response validation  | Truth/contradiction and budget tests pass             |
| M7 Learning                    | Recipes, site/global/user memory, shadow promotion, rollback                              | Regression suite prevents known failures              |
| M8 Analytics and orchestration | Ledger, attribution, experiments, exports, n8n                                            | Event, privacy, and statistical-honesty gates pass    |
| M9 Hardening                   | Permission, security, accessibility, performance, backup/restore                          | Release audit passes                                  |

## Current `0.2.0` position

- M0 is complete. Strict CI, browser tests, migration tests, and security workflows are green on the current feature branch. Development/source verification is separated from installed-runtime verification, so the production native environment does not require developer-only Ruff/Pytest packages.
- M0.5 is physically proven for the hosted iPhone workflow: the owner workspace operates while the Mac is off and the phone can see the enrolled desktop device. The remaining cross-device release gap is hosted-frontend reproducibility/parity: the exact deployed `chatgpt.site` frontend source is not yet attached to this repository, so the shared device-count/conflict/autosync/review-backlog contract cannot yet be claimed as deployed on every hosted surface.
- M1 is advanced. The desktop editor exposes a broad protected application profile, coalesces rapid autosaves, confirms protected facts, synchronizes encrypted profile state with optimistic version checks, and preserves confirmed protected facts during device convergence. Current and future sponsorship are separate protected facts; ambiguous generic sponsorship wording remains manual because it does not identify which question is being asked. Repeatable education/employment/project/certification/language contracts now have durable SQLite tables. New résumé uploads validate PDF/DOC/DOCX input, hash the original bytes, record family/version metadata, and application reviews freeze the selected résumé hash when available. Hosted-workspace field parity, UI migration to the repeatable record model, and the final owner recovery-key drill with synthetic data remain M1 exit gates.
- M2 includes all-frame aggregation, open Shadow DOM discovery, stable control fingerprints, History API and semantic-attribute rescanning, grouped radio discovery, and broad deterministic identity/address/education/employment/authorization semantics. Controlled ARIA comboboxes now expose only their owned options and can fill exact already-present options with post-action verification and rollback on failure. Async autocomplete, dates, multi-selects, section/navigation semantics, validation-state modeling, richer iframe cases, and unusual dynamic controls remain incremental work.
- M3 now has one deterministic answer-resolution policy shared by the application model and the real desktop side panel. The resolver returns `READY`, `REVIEW`, or `UNRESOLVED`; missing/unmapped facts are not invented, generated/non-authoritative facts cannot become ready answers, and protected/sensitive/high-risk facts require review. Trusted contradiction detection, explicit-only knockout rules, salary-range review policy, and a pre-flight gate that blocks action unless every item is ready are implemented. A shared review-backlog helper scopes counts to active application pages so historical discovery cannot legitimately be presented as current review work. Job-specific extraction of employer knockout rules and richer source-level contradiction aggregation remain.
- M4 supports guarded native text, textarea, select, radio, checkbox, contenteditable, open-Shadow-DOM controls, and a verified exact-match ARIA combobox subset. Radio groups are value-aware, ambiguous checkbox values fail without mutation, and unsupported combobox options restore the original value rather than claiming success. Employer file controls remain manual. Async custom widgets, richer state waits, dates, autocomplete, multi-selects, portaled menus, and promoted interaction recipes still need runtime integration.
- M5 now has a deterministic checkpoint-first planner in addition to application-state contracts and synchronized application snapshots. The planner pauses for CAPTCHA/MFA/OTP/identity/authentication checkpoints, refuses automatic final submission by construction, requires a ready pre-flight gate, takes one approved visible fill at a time, verifies fill/navigation results, and serializes restart checkpoints with selected résumé identity/hash. Checkpoints are durably stored in SQLite migration `003`. The live extension still needs the persistent Observe → Plan → Act → Verify → Rescan controller, page-to-state inference, navigation execution, and physical crash/interruption recovery tests before M5 exits.
- M6 has a substantial provider-independent truth/safety layer. Evidence graph/retrieval excludes generated text from authoritative retrieval by default, excludes protected evidence unless explicitly requested, builds bounded context, detects selected contradiction edges, and validates generated claim-to-evidence structure and word limits. Explicit model-pricing contracts, pre-request budget decisions, durable AI usage accounting, and a deterministic router refuse generation when pricing/context/budget gates are missing or stale. A Responses API adapter exists behind the gate with `store: false`, strict structured claim/evidence output, response-status/refusal checks, token-usage requirements, and a local output-token ceiling. It is not exposed as a user-facing generation command yet, and no real provider request/spend has been performed. Résumé/evidence parsing into durable evidence nodes, end-to-end generated-draft validation, pricing refresh governance, and physical provider smoke tests remain before inference can be enabled.
- M7 has a first safe learning foundation. Structural component fingerprints, shadow interaction recipes, verified-only attempt metrics, promotion thresholds, and rollback after consecutive verified failures are implemented, and migration `004` plus the native learning/analytics store persist recipes/attempts. Recipe actions intentionally exclude final-submit and security-bypass actions. Live recipe capture/execution, site/global/user memory composition, and Teach-MUNSHI demonstrations remain.
- M8 has an initial privacy/statistical-honesty foundation. Durable application outcomes, opaque attribution tokens, deterministic salted experiment assignment, variants/assignments, and minimum-sample gates exist. Experiment summaries explicitly avoid calling a small sample a winner and describe rates without implying causality. n8n still has only the signed event bridge foundation; exports, portfolio-event ingestion, production orchestration, experiment UI, and analytics dashboards remain.
- M9 hardening is continuous. AI preferences are backed up outside secret storage, profile synchronization has explicit protected-fact convergence, the macOS Keychain write path no longer places the OpenAI key in process arguments, and migrations `003`/`004` are covered by native and migration CI. A physical Mac migration/Keychain smoke, synthetic owner recovery drill, hosted-frontend parity fix, permission/accessibility/performance review, backup/restore exercise, privacy review, and final release audit remain before release readiness.

No milestone may add automatic final submission before the user-configurable final approval checkpoint exists.

Connecting an AI provider does not change the truth boundary: unverified or protected application claims may not be generated, inferred, approved, or filled silently.

Ambiguous generic sponsorship wording remains manual even though dedicated current- and future-sponsorship facts now exist; the system must know which sponsorship question the employer is asking before selecting either fact.

M0.5 is required before M1 stores real private data in the cloud. It must follow [Mobile and cross-device architecture](MOBILE_AND_CROSS_DEVICE_ARCHITECTURE.md), including the no-paid-service-without-approval rule and the distinction between a mobile foundation build and physical-iPhone verification.
